# รายงานการวิเคราะห์ตัวแปร: ผู้อำนวยการสำนักการแพทย์ กทม

> **บทบาท:** ผู้บริหารระบบการแพทย์ กทม — ต้องการข้อมูลคลินิกเชิงลึก ผลลัพธ์ทางการแพทย์ คุณภาพบริการ และการจัดสรรทรัพยากรทางการแพทย์ทั่ว กทม
>
> **แหล่งข้อมูล:** homehealth.csv · homevisit.csv · labhealth.csv · labhealthext.csv · pt.csv · pthistory.csv · vitalsignslf.csv
>
> **ข้อมูลเสริม:** `clinic_latlong.xls` (14,092 สถานบริการพร้อมพิกัด lat/lng) · ArcGIS REST APIs 28 endpoints (เอกสารแนบ ๒)
>
> ---
>
> ### ประเด็นที่ ผอ.สำนักการแพทย์ Raise ขึ้นมาจริง (จากการประชุม)
> 1. **Diseases x Lab Result** — ต้องวิเคราะห์ข้ามระหว่างโรคกับผลแลป
> 2. **Cross & Comorbidity** — ดูภาวะโรคร่วมหลายโรคในคนเดียว
> 3. **Data Cleaning** — จะทำความสะอาดข้อมูลอย่างไร
> 4. **ผู้ตรวจซ้ำ** — คนที่มาตรวจมากกว่า 1 ครั้ง มีเท่าไหร่ แนวโน้มสุขภาพเปลี่ยนอย่างไร
> 5. **ตำแหน่งสถานบริการ** — มีพิกัด lat/lng ของศูนย์ใน กทม ไหม

## ส่วนที่ 1: แผนที่ กทม (Map Dashboard)

### 1.1 แผนที่ระบบบริการสุขภาพ — พร้อมพิกัดจริง

| ตัวแปร | แหล่ง | สิ่งที่แสดงบนแผนที่ |
|---|---|---|
| `HPTCODE` | ทุกไฟล์ | ศูนย์บริการสาธารณสุขทั้งหมด — pin พร้อม pop-up สรุปผลงาน |
| `DISTRICTBKK` | vitalsignslf.csv | แบ่งเขตสุขภาพ — กุญแจหลักในการ plot |
| `LOCATION` | vitalsignslf.csv | จุดให้บริการ (ศูนย์/เชิงรุก/ชุมชน) |
| `ORGBMA` | homevisit.csv | หน่วยงานที่รับผิดชอบ |
| `PID` | ทุกไฟล์ | ปริมาณผู้ป่วยต่อศูนย์ — bubble size |
| `FIRSTSTF`, `LASTSTF` | ทุกไฟล์ | จำนวนบุคลากร — อัตราส่วนเจ้าหน้าที่ต่อผู้ป่วย |

> **ตอบประเด็น "มีตำแหน่งของสถานบริการใน กทม ไหม?"**
>
> **มี** — ไฟล์ `clinic_latlong.xls` มี **14,092 รายการ** พร้อมคอลัมน์:
>
> | คอลัมน์ | คำอธิบาย |
> |---|---|
> | `ct_id`, `ct_name` | ประเภทสถานบริการ (เช่น โรงพยาบาลในกทม., จุด AED) |
> | `c_name` | ชื่อสถานบริการ |
> | `address` | ที่อยู่ |
> | `tel` | เบอร์โทรศัพท์ |
> | `hcode` | รหัสสถานบริการ — **join กับ `HPTCODE` ในข้อมูลคัดกรองได้** |
> | **`lat`**, **`lng`** | **พิกัด latitude/longitude** — plot ลงแผนที่ได้ทันที |
>
> นอกจากนี้ยังมี **ArcGIS REST APIs** (เอกสารแนบ ๒) อีก 2 endpoint ที่ใช้ได้:
> - **ศูนย์บริการสาธารณสุข** (Layer 96) — `cpudgiportal` server
> - **โรงพยาบาล** (Layer 16) — `bmagis` server, WKID 4326

## ส่วนที่ 3: ประเด็นเชิงวิเคราะห์ที่ ผอ. Raise (ตอบคำถามจากการประชุม)

### 3.1 Diseases x Lab Result — วิเคราะห์ข้ามโรคกับผลแลป

**แนวคิด:** Join ข้อมูลผ่าน `PID` + `VSTDATE` ระหว่าง homehealth/vitalsignslf กับ labhealth เพื่อดูว่าผู้ป่วยแต่ละโรคมีผลแลปอย่างไร

| โรค (ตัวแปร) | Lab ที่ควร Cross (ตัวแปร) | คำถามที่ตอบได้ |
|---|---|---|
| `DM`=1 (homehealth) | `FBS`, `DTX`, `BLDSUGAR` (labhealth) | ผู้ป่วย DM ควบคุม FBS ได้กี่ % (FBS <130)? |
| `DM`=1 | `EGFR`, `CRTININE`, `PROTEIN` (labhealth) | DM ที่มี CKD ร่วมกี่ %? (EGFR <60) |
| `DM`=1 | `CHOLEST`, `TRIGLY`, `HDL`, `LDL` (labhealth) | DM ที่ไขมัน LDL >100 กี่ %? |
| `HPT`=1 (homehealth) | `HBPN`, `LBPN` (vitalsignslf) | ผู้ป่วย HPT ที่ BP ยังไม่ถึงเป้า (<140/90) กี่ %? |
| `HPT`=1 | `EGFR`, `CRTININE` (labhealth) | HPT ที่ไตเสื่อมกี่ %? |
| `KIDNEY`=1 (homehealth) | `EGFR`, `CRTININE`, `BUNRS` (labhealth) | CKD staging distribution (G1–G5) |
| `HRT`=1 (homehealth) | `EKG` (vitalsignslf), `CHOLEST`, `LDL` | โรคหัวใจที่ EKG ผิดปกติ + LDL สูงกี่ %? |
| `CHLTR`=1 (homehealth) | `CHOLEST`, `TRIGLY`, `HDL`, `LDL` | ผู้ป่วยไขมันที่ค่าถึง target กี่ %? |
| `STROKE`=1 | `HBPN`, `LBPN`, `FBS`, `LDL` | Stroke ที่ยังมี risk factors ไม่ควบคุมกี่ %? |
| `ASTH`=1 / `EMPHY`=1 | `CHEST` (vitalsignslf) | โรคปอดที่ CXR ผิดปกติกี่ %? |

**SQL ตัวอย่าง:**
```sql
SELECT 
  CASE WHEN h.DM = 1 THEN 'DM' ELSE 'Non-DM' END as disease_group,
  AVG(CAST(l.FBS AS FLOAT)) as avg_fbs,
  SUM(CASE WHEN CAST(l.FBS AS FLOAT) >= 126 THEN 1 ELSE 0 END) * 100.0 / COUNT(*) as pct_uncontrolled
FROM homehealth h
JOIN labhealth l ON h.PID = l.PID AND h.VSTDATE = l.VSTDATE
WHERE l.FBS IS NOT NULL AND l.FBS != ''
GROUP BY disease_group
```

### 3.3 Data Cleaning — แนวทางทำความสะอาดข้อมูล

| ปัญหา | ตัวแปรที่เกี่ยว | วิธี Clean |
|---|---|---|
| **ข้อมูลซ้ำ** | `PID` + `VSTDATE` + `HPTCODE` ในทุกไฟล์ | Deduplicate — เก็บ record ล่าสุด (`LASTDATE`) กรณี PID+VSTDATE ซ้ำ |
| **ค่าว่าง (Missing)** | ทุกตัวแปรคลินิก | นับ % missing ต่อคอลัมน์ — ถ้า >80% missing ควรพิจารณาตัดออก |
| **รายการยกเลิก** | `CANCELST`=1 | **ต้องกรอง `CANCELST` != 1 ออกก่อนวิเคราะห์ทุกครั้ง** |
| **Flag ข้อมูล** | `FLAG` | ตรวจสอบค่า FLAG — อาจหมายถึงข้อมูลไม่สมบูรณ์ |

| **Encode ซ้ำ** | `HPTCODE` ใน CSV vs `hcode` ใน clinic_latlong.xls | Mapping table — `HPTCODE` อาจเป็นรหัสย่อ (chr, cnt, bkt, srt...) ต้อง map กับ hcode ใน xls |

### 3.4 ผู้ตรวจซ้ำ — Longitudinal Health Trends

**แนวคิด:** Group by `PID` แล้วนับจำนวน `VSTDATE` ที่ไม่ซ้ำ → ได้จำนวนครั้งที่แต่ละคนมาตรวจ

| การวิเคราะห์ | ตัวแปร | Output |
|---|---|---|
| **จำนวนครั้งตรวจต่อคน** | `PID`, `VSTDATE` (ทุกไฟล์) | Distribution: มา 1 ครั้ง (X%), 2 ครั้ง (Y%), >=3 ครั้ง (Z%) |
| **ระยะเวลาติดตาม** | `FIRSTDATE` ↔ `LASTDATE` (ทุกไฟล์) | Median follow-up duration |
| **BP Trend** | `PID` → `VSTDATE` → `HBPN`, `LBPN` (vitalsignslf) | Spaghetti plot / median BP ครั้งที่ 1 vs ครั้งที่ 2 vs ครั้งที่ 3 |
| **FBS Trend** | `PID` → `VSTDATE` → `FBS` (labhealth) | ค่า FBS ลดลงหลังคัดกรอง+ให้คำแนะนำหรือไม่ |
| **BMI Trend** | `PID` → `VSTDATE` → `HEIGHT`, `WEIGHT` (vitalsignslf) | น้ำหนักลดลง/เพิ่มขึ้นหลังได้รับคำแนะนำ |
| **PHQ-9 Trend** | `PID` → `VSTDATE` → `SCN9Q1`–`SCN9Q9` (vitalsignslf) | คะแนนซึมเศร้าดีขึ้นหรือแย่ลงหลังส่งต่อ |
| **Lipid Trend** | `PID` → `VSTDATE` → `CHOLEST`, `LDL` (labhealth) | ค่าไขมันลดลงหลังปรับพฤติกรรม/ให้ยาหรือไม่ |
| **Lost to follow-up** | `PID` ที่มี visit ครั้งเดียวแล้วไม่กลับมา | อัตรา lost to follow-up — ศูนย์ไหนสูงสุด? |
| **Drop-off analysis** | `CANCELST`, `CANCELDATE` | คนยกเลิกนัดตอนไหน/ศูนย์ไหน/กลุ่มอายุไหน |

**SQL ตัวอย่าง:**
```sql
-- หาผู้ตรวจซ้ำ
SELECT PID, COUNT(DISTINCT VSTDATE) as visit_count
FROM vitalsignslf
WHERE CANCELST != 1
GROUP BY PID
HAVING visit_count > 1
ORDER BY visit_count DESC
```
